## 2. Logic Chain
1. *Step 1 (Darwin Engine Visibility)*: `shared/build.gradle.kts` uses `applyDefaultHierarchyTemplate()`. When `iosArm64()` and `iosSimulatorArm64()` targets are configured, Gradle automatically creates the `iosMain` intermediate source set. Because `iosMain` is already generated by the template, attempting to use `val iosMain by creating` will fail with a duplicate source set error; `val iosMain by getting` or `iosMain.dependencies` must be used. Adding `implementation("io.ktor:ktor-client-darwin:3.5.2")` to `iosMain` supplies the native Apple `NSURLSession` engine to all iOS compilation tasks.
2. *Step 2 (Shared Ktor & Multiplatform Dependencies in commonMain)*: Moving `ktor-client-core:3.5.2`, `ktor-client-websockets:3.5.2`, `ktor-client-content-negotiation:3.5.2`, and `ktor-serialization-kotlinx-json:3.5.2` from `jvmSharedMain` to `commonMain.dependencies` ensures that both JVM and Darwin platforms have access to the common Ktor API surface.
3. *Step 3 (Coil Network Ktor3 Binding)*: Compose Multiplatform UI components using `AsyncImage` require a `NetworkFetcherFactory` to load network images. Coil 3 decoupled network engines into separate modules. Adding `api("io.coil-kt.coil3:coil-network-ktor3:3.0.4")` to `sharedUi/build.gradle.kts` (matching `coil-compose:3.0.4`) enables Coil to fetch images on iOS using Ktor and `NSURLSession` via Kotlin/Native's `@EagerInitialization` service loader target.
4. *Step 4 (JVM Artifact Isolation Boundary)*:
   - `ktor-client-okhttp:3.5.2` must strictly remain in `jvmSharedMain.dependencies`.
   - `org.jsoup:jsoup:1.22.2` must strictly remain in `jvmSharedMain.dependencies` (used only in `Genius.kt`).
   - `com.microsoft.onnxruntime:onnxruntime:1.20.0` must strictly remain in `jvmSharedMain.dependencies` as `compileOnly`.
   - `com.github.TeamNewPipe:NewPipeExtractor:v0.26.3` must strictly remain in `jvmSharedMain.dependencies` as `compileOnly`.
   - `com.squareup.okhttp3:mockwebserver:5.3.2` must strictly remain in `jvmTest.dependencies`.
   This quarantine ensures that no Java bytecode or JNI artifacts leak into iOS compilation units.
5. *Step 5 (Version Alignment)*: In `shared` and `sharedUi`, aligning `kotlinx-serialization-json` to `1.11.0` (matching Ktor 3.5.2) and `kotlinx-coroutines-core` to `1.10.2` (or `1.11.0`) avoids version skew and conflicting metadata warnings across targets.
